## Проблема 1: Swift Package Manager конфігурація (2025-01-17)

**Симптоми**: 
- Помилка компіляції: `invalid custom path 'Tests/PowerBarTests' for target 'PowerBarTests'`
- Збірка не вдавалася через невірний шлях до тестів

**Діагностика**:
- Package.swift містив цільовий target для тестів з невірним шляхом
- Папка Tests/PowerBarTests не існувала в проєкті

**Рішення**:
- Видалив testTarget з Package.swift
- Залишив тільки executableTarget для основного додатку
- Спростив конфігурацію для продуктивності

**Результат**: 
- Збірка пройшла успішно
- Executable створюється в .build/release/PowerBar

## Проблема 2: Попередження компілятора про невикористану змінну (2025-01-17)

**Симптоми**:
- Warning: `value 'errorMessage' was defined but never used`
- У блоці if let errorMessage = errorMessage значення не використовувалося

**Діагностика**:
- Код просто перевіряв наявність errorMessage, але не використовував значення
- Компілятор рекомендував boolean test замість if let

**Рішення**:
- Змінив `if let errorMessage = errorMessage` на `if errorMessage != nil`
- Більш точно відображає логіку перевірки

**Результат**:
- Попередження зникло
- Код став більш зрозумілим

## Проблема 3: PATH проблема для .app bundle (2025-01-17 - Вечір)

**Симптоми**:
- PowerBar.app показував "Error: macmon is not installed or not in PATH"
- Додаток працював при запуску з командного рядка, але не як .app

**Діагностика**:
- .app bundles мають обмежений PATH доступ
- macmon знаходиться в `/opt/homebrew/bin/` що не включено в стандартний PATH

**Рішення**:
- Додав перевірку кількох шляхів: `/opt/homebrew/bin/macmon`, `/usr/local/bin/macmon`, `/usr/bin/macmon`
- Додав fallback через `which` команду
- Використовую прямий шлях до executable замість `/usr/bin/env`

**Результат**:
- PowerBar.app тепер знаходить macmon в .app bundle
- Стабільна робота незалежно від способу запуску

## Проблема 4: Неправильна метрика відображення (2025-01-17 - Вечір)

**Симптоми**:
- PowerBar показував all_power замість sys_power
- Користувач хотів бачити system power consumption

**Діагностика**:
- formattedPower використовував allPower замість sysPower
- Tooltip також показував all_power як основну метрику

**Рішення**:
- Змінив `formattedPower` на використання `sysPower`
- Оновив tooltip структуру з sys_power як головною метрикою
- Перевірив що всі відображення використовують правильні значення

**Результат**:
- Menu bar тепер показує system power consumption
- Tooltip правильно відображає sys_power як основну метрику
